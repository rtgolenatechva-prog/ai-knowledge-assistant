## 2. What We're Building

AI Knowledge Assistant web app: JWT-based register/login/logout, AI chat via OpenRouter (free model), conversations saved/listable/resumable/deletable, deployed publicly on free tiers.

## 3. Tech Stack

| Layer | Choice |
|---|---|
| Frontend | Next.js (App Router) + TypeScript |
| Backend | Express + TypeScript (separate REST API service) |
| Database | PostgreSQL via Supabase |
| ORM | Prisma |
| Auth | Custom JWT (bcrypt + jsonwebtoken), not Supabase Auth |
| AI | OpenRouter API, free model (verify availability at build time) |
| Frontend deploy | Vercel |
| Backend deploy | Render free tier (Railway/Fly.io fallback) |
| DB hosting | Supabase |

## 4. Architecture

```
/frontend  (Next.js, TS, Vercel)
  - Register / Login / Logout pages
  - Protected chat dashboard (redirect to login if no valid JWT)
  - Conversation sidebar (view, resume, delete)
  - Chat UI (send prompt, view response, loading/error states)
  - JWT stored client-side, attached to API requests

/backend  (Express, TS, Render)
  - POST /auth/register
  - POST /auth/login
  - POST /auth/logout
  - JWT verify middleware on protected routes
  - GET/POST /conversations
  - GET/DELETE /conversations/:id
  - POST /conversations/:id/messages  (calls OpenRouter, saves + returns response)
  - Central error-handling middleware

/database (Postgres via Supabase, Prisma-managed)
  - users (id, email, password_hash, created_at)
  - conversations (id, user_id FK, title, created_at)
  - messages (id, conversation_id FK, role, content, created_at)
```

## 5. Build Order

1. **Scaffolding** — init frontend + backend projects, Prisma schema, .env setup, git init/first commit
2. **Auth** — register/login/logout endpoints, JWT middleware, frontend auth pages + protected routing, manual test of full loop
3. **AI Chat** — OpenRouter integration (simple request/response), conversation + message CRUD, chat UI with loading/error states
4. **Conversation History** — sidebar list/resume/delete, cascade delete via Prisma
5. **Polish** — responsive UI, loading/error states everywhere, code cleanup
6. **Deploy** — backend to Render, frontend to Vercel, env vars, full end-to-end live test
7. **Submission** — README (setup, stack, run instructions, demo URL, known limitations), final push, gather repo + demo links

## 7. Testing / Error Handling

- Manual auth loop test before proceeding past Phase 2
- Error states for: registration failure, login failure, AI call failure/rate-limit, network errors

## 8. Out of Scope (YAGNI)

- Refresh token complexity (short-lived access token is enough)
- JWT blacklist for logout (stateless is fine unless time allows)
- Streaming AI responses (simple request/response only)
- Fancy mobile design (mobile-friendly baseline only)
